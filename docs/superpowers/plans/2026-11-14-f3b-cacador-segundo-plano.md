# F3b Caçador em segundo plano Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Juan turns a Caçador on, closes the tab, comes back later and its new companies are in LEADS, with proof and no repeats; the agent pauses itself with a warning at the AI ceiling; and a baseline report of the first run against `data/gold/` proposes the weekly lead goal (J3).
**Architecture:** Migration 0010 gives agents a real life cycle (Ligar/Pausar, next run, max 3, frozen config, archive rules) and a sessionless "hunter path": `hunter_*` SQL functions, callable by `anon` only with the E1 scheduler token (`scheduler_authorized()`), each scoped to ONE agent run (and through it to the agent's workspace), writes only while holding that run's step lease. A new `HunterResearchStore` implements the existing `ResearchStore` over those RPCs, so the unchanged engine (`advance`, one bounded step per call) runs with no user. A separate cron route `/api/hunter/tick` (maxDuration 300, C7) advances due runs for up to 120 s per call; pg_cron calls it every 2 minutes. AI spend goes through the same reserve/settle rules (refactored into `*_core` functions), charged to the workspace and to the agent's creator (C5). Scheduled runs skip companies already in LEADS (C4), using the `leads` table of F3a.
**Tech Stack:** Next.js 16.4.5 App Router, React 19.3, TypeScript, zod 4, Supabase/Postgres + pg_cron/pg_net (PGlite in tests), vitest (node env, no DOM).
**Spec:** `kolmeia/docs/superpowers/specs/2026-11-14-kolmeia-3-areas-design.md` — sections 6.5, 6.6, 6.8, 7.1, 10 (row F3), decisions J3, C4, C5, C6, C7, C9. Carries F2 blockers 1, 2, 3, 5 and minors (archive confirm, `finishHunter` guarded by `status = draft`) from `kolmeia/.superpowers/sdd/f2/progress.md`.

`APP` = `kolmeia/app`. Every command runs from `APP` unless it starts with `cd`.
