# F3c-2 Qualificador (esteira em cascata + Gastos) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every lead is qualified by itself, cheapest step first (P1 juntar, P2 site, P3 Places, P4 IA leve, P5 IA forte), every value shows where it came from and a level 0-4; the Qualificador never spends past its US$ 5/day (editable) or a lead's cap; P5 runs automatically on contactable leads that match the approved profile (switchable) and on demand with an estimate; a "Gastos" screen shows where each cent went.
**Architecture:** Migration 0012 gives leads a level computed from `lead_fields` (F3c-1) and research proof, a per-workspace `qualifiers` settings row, a `qualifier_queue`, `ai_calls.lead_id`, and a token-gated sessionless `qualifier_*` path built exactly like F3b's `hunter_*` path (scheduler token, tick lease, per-lead claim, reserve/settle through F3b's `*_core` functions). A `runQualifierTick` runs inside F3b's cron route after the Caçador (own budget). Per claimed lead, `qualifyLead` runs the cascade in memory (pages read by P2 feed P4) and writes values through RPCs. P2 is a plain HTTP reader with SSRF, robots, rate and size limits; P3 is the official Places API, off without a key; P4 is a new Haiku task; P5 reuses the research verify task under the task name `qualify_deep`.
**Tech Stack:** Next.js 16.4.5 App Router, React 19.3, TypeScript, zod 4, Supabase/Postgres + pg_cron (PGlite in tests), Node `node:http`/`node:https`/`node:net`, vitest (node env, no DOM).
**Spec:** `kolmeia/docs/superpowers/specs/2026-11-14-f3c-lista-qualificador-cobertura-design.md` — sections 5.2, 5.3, 5.5, 6, 7, 9, 10 (rows F3c-2, F3c-3); decisions J-1, J-2, J-3, J-4, K-3, K-4, K-5, K-10, K-11, C-a, C-b, C-c, C-f. Needs `2026-11-14-f3c-1-subir-lista.md` done. Sibling: `2026-11-14-f3c-3-perfil-cobertura.md` (sets `profile_match`).

`APP` = `kolmeia/app`. Every command runs from `APP` unless it starts with `cd`.

- Queue (K-4): every lead is enqueued at birth (`next_step 'p1'`, `priority_hunter` = Caçador origin); new imported values re-queue a finished lead (not a `dead` one).
